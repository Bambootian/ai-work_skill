全景

三个嵌套的循环，一个船长，一层硬约束

整套工作流可以压成一张图：task 内环嵌在 change 环里，change 环嵌在 value 环里。人在最外面只做四类决定；fresh-context 的 critic、reviewer、方向反方从侧面盯着每一环；hooks 在最底下做确定性强制。

分层

四层工程模型，约束自底向上下沉

每条约束都有它该住的层。能让 harness 强制的不写进提示词；能做成模板必填槽位的不写进 skill；只有每一步都需要、哪里都放不下的，才进 CLAUDE.md 常驻。提示层做减法，harness 层只看误报率。

Harnesshooks / settings · 确定性

约束下沉原则：每写一条约束，自底向上问

  1. 能 hook 强制吗？能 → 写脚本进 hooks/，跑 echo 用例
  2. 能变成模板必填槽位吗？能 → 进 change.md / backlog.md / CLAUDE.md 模板
  3. 能做成 skill 按需注入吗？能 → 进 change-loop / value-review 正文
  4. 都不能，且每步都需要？才进 CLAUDE.md 常驻（Hard Rules 只有 7 条）
加约束前再答四问：它替换掉了什么；热存储净减多少；防哪种失败；近几周在当前模型上出现过吗。用新的重流程修旧的重流程是头号错误。

工程全流程

从立项到收官：一次立项，无数次 change，按里程碑回顾

立项只做一次，把 North Star、主线路径、项目参数、hooks 落到文件。此后每个 session 从 backlog Now 接手，每个 change 走 change-loop，到检查点跑 value-review，收工时把状态写回文件。

第一步：立项（project-bootstrap，一次性）

顺序承重：先 brainstorm，文档从其结果回填。先填模板必然是空的或编的。

此后每个 session 的节奏

文件携带状态，不靠对话记忆。Session Start 的检查顺序固定；回顾触发检查发生在下一个 change 路由之前。

Change Loop

一个 change 的六站：路由、契约、内环、Gate、Close、收工

每个 change 是一个有契约、有预算、明确出口的循环。R1 以上的产物同一个形状：一个 change 一个 change.md，能力主 spec 在 change 内就地改，差异就是 git diff，归档就是 git mv。

Route

任何 spec / 代码之前。先查回顾触发，读要动的代码与主 spec，按 novelty × reversibility × blast radius 声明两行 + BASE。

  • grep backlog 支线与 watchlist，命中列一行
  • 拿不准取高一级

契约

Loop Contract 写在 change.md 头部：Outcome / Verify / Budget / Exit（+ Decided:）。动契约直接改主 spec。

  • Spec 自检：Critic: 行按内容判定派不派
  • [blocking] 修完进循环，不等人批

内环

每 task：读 scenario → 实现 → 绿 → 自审 diff → commit → 勾 Tasks。task 之间不请示。

  • 只在绿提交；最后绿 commit 是锚点
  • 每次失败尝试记注记

Gate

fresh-context reviewer 只看代码 diff + change 文件 + spec diff，不看产生代码的推理。

  • 底线：动产品代码 / 数据契约 / 架构的 R1+ 至少一个 reviewer
  • 派不出去 → ungated，不 inline 替代

Close

证据 gate。五步一个 commit archive(<id>)：Close 段真输出、核主 spec、git mv 归档、backlog、可选 lint。

  • BLOCKED 不归档，留在目录即在途标记

Land the plane

更新 change 文件；backlog Now 整段覆盖：主线位置、下一步、悬而未决。

  • 覆盖前先读旧 Now，悬而未决只能核销或结转

第 ① 站 · 路由：四个档位

轴：novelty 新不新reversibility 可不可逆blast radius 爆炸半径在代码里，读过再路由写法：Route: R<0-3> — 一行理由
R0
直行

可逆、无 spec / 架构 / 数据契约影响。

  • 开工前一句 verify 命令与期望
  • 自审 diff，commit 前展示输出
  • 免 gate、不建文件、不写 backlog
R1
轻量

单 capability，无新架构决策、无新外部依赖。

  • change.md 全形状
  • critic / gate 按内容判定
R2
标准

新 capability、跨模块或新外部依赖。

  • critic 判定后直接进循环，不等人批
  • 只动架构决策或数据契约也是 R2：AI 定并写失效前提
R3
方向

动 North Star、板块终态 / 判据、主线段，或花费超项目参数。

  • 方向交人定；反方按触发表先派，并排表一起交人
  • 之后按 R2 走；brainstorm 只在立项与 R3

主线: 行四选一：第 N 步 <change-id> ｜ 第 N 步前置（只读测量 / enabling）｜ 支线（来源）｜ 等待期活。不在 backlog 主线段里的一律支线。

第 ② 站 · change.md 解剖

只有三个段名和一个行名是机器级接口（minor 版本内只增不改）；其余段可增删。头部三行决定 diff 基线，金色是路由与基线，青色是接口。

docs/changes/<id>/change.md
# <change-id> Route: R2 — 新 capability，跨两个模块 主线: 第 3 步 <change-id> BASE: a1b2c3d
BASE 是加入 change.md 那个 commit 的父。critic、gate、WITHDRAWN、归档后复原都以它为 diff 基线：git diff <BASE> -- <spec 文件>
## Loop Contract - Outcome: 谁能观察到什么不同（操作者 / North Star 用户） - Verify: 具名命令 + 期望输出 - Budget: max 天数 - Exit: DONE | BLOCKED | SPLIT - Decided: 替人定的事，≤5 条，难撤回标 ⚠ - Critic: <视角 | 免> — 理由 - Gate: <视角 | 免> — 理由
「测试通过」四个字无效。Outcome 不用代号。免跑 critic / gate 必须指出具体信号（只动文档、产物整理）；该跑的信号：新数据契约、架构决策、预登记口径、花真钱真跑。
## Why ≤10 行人话 ## Non-goals
大投入前的方向反方并排表放在 Why 里，不另写 retro。
## Spec 改动 - docs/specs/<cap>/spec.md: ADDED <Requirement> - docs/specs/<cap>/spec.md: MODIFIED / REMOVED（理由） - Decision <ID> 新增 / <ID> → Superseded
只列清单，正文在主 spec。在途期主 spec 写的是意图；并行 change 必须各占一个 worktree，否则同分支就地改是静默覆盖。
## Decisions ★ = 已写进主 spec Architectural Decisions ## Scenarios WHEN … THEN … ## 流程 可选，≥3 阶段带分支才画
决策写进主 spec 时带「为什么」+ Fails when + Source，只写一次；被推翻的旧决策首行改 Superseded。
## Tasks - [ ] 1.1 <任务> — 验证：<命令 → 期望输出>
spec 范围内 AI 自治改 Tasks；动 spec / 范围 / 预算 = SPLIT，停下交人。
## 注记 失败注记 append：task id + tried / observed / hypothesis
对话记忆不跨 compaction，文件跨。
## Close 每条 Verify 真输出 / Outcome / Gate 行 / Decided 聚合 / 出口态 / 读数
归档后的订正追加于此，不进 backlog / decisions。

第 ③ 站 · 内环与它的失败路径

第 ④ 站 · 两个 fresh-context 评审的标准

SPEC CRITIC · 成文后、进循环前 · 逐条 yes/no
  1. 意图三向覆盖 Why ↔ spec diff 的 Requirement / Decision ↔ Tasks，缺一列出
  2. 对既有代码的每个假设去读代码核实 不信 change 文件的转述，最常见的漏
  3. 外部 API / 库每个引用实查存在与签名
  4. 范围 Tasks 有契约没要求的？Non-goals 盖住蠕变了吗？
  5. 可验证 每个 Requirement 有成功 + 失败 scenario；Verify 真覆盖；末 task 端到端
  6. 决策 每条带为什么 + Fails when + Source；备选真被考虑过
  7. 必填：最不放心的 3 处 即使整体 PASS；报 PASS 前先写你试过怎么打它
GATE REVIEWER · 代码收尾
  • [blocking] 违反 spec / 契约，或真实缺陷（正确性 / 资源泄漏 / 数据丢失 / 安全），必修
  • [nit] 风格与「可以更好」，记录不追，防评审驱动的过度工程
  • 两条具名任务：挑 3 条最强断言在粘回的输出里找反证；回答实测覆盖范围是否等于断言范围
  • 单 reviewer 必核 Verify 命令是否真覆盖 Outcome 与 scenarios，弱验证是最大漏风口
  • 多 reviewer 冲突 → AI 裁定记 Decided:，冲突点通常正是 spec 的真模糊处

第 ⑤ 站 · Close 五步，一个 commit

Close 段 append

每条 Verify 命令的真实输出，不概述、不「应该过」；Outcome 一行；Gate 行；Decided 聚合；出口态。

核主 spec

本 change 的决策都带 Source、被推翻的已 Superseded、新 spec 的 Purpose 非占位。

归档 = git mv

git mv <changes>/<id> <changes>/archive/<date>-<id>；BLOCKED 不归档；WITHDRAWN 先确认只有本 change 的 commit 再 git apply -R。

backlog

主线步 DONE 才打勾；支线完成即删行；Now 整段覆盖。留给未来的条件优先写到会被读到的地方。

可选 lint

grep -L '#### Scenario' specs/*/spec.md 应为空。归档后复原本 change 改了哪些契约：git diff <BASE>..<archive commit>。

出口态

DONE

Verify 全绿 + Outcome 落地；底线 gate 跑了或按判定免跑

DONE-ungated

底线 gate 该跑没跑；补跑后 backlog 才打勾

BLOCKED

blockers 附后，升级给人；文件留在 changes 目录即在途标记

SPLIT

超预算或复合任务 → 提拆分方案；子 change 抄父的 BASE 行

派发

Subagent：单层扁平扇出，禁止孙 agent

子代理看不到主循环的任何上下文，所以约束必须逐字重述，每次都是。派 reviewer、critic、方向反方、隔离 subagent 是项目 CLAUDE.md 里的常设授权，不请示；派不出去就报原因、标 ungated，绝不在本会话 inline 替代。

dispatch-prompt.md · 六个 REQUIRED 槽位
## Model
默认继承会话模型；浏览器 / 抓取类必降 Sonnet；方向反方用最强可用模型
## Objective
一个任务，一个产出。不是两个
## Context
change-id、文件路径、已存在什么；最小必需，无对话史
## Constraints - 项目硬规则（粘 CLAUDE.md 行） - 测试命令纪律（永不自设 escape 变量） - Loop contract（Outcome / Verify / Budget） - Scope：只动 <files>；无顺手改动
逐字重述，不摘抄改写。省略任何 REQUIRED 槽位 = 派发无效
## Output format
返回数据不是叙事；≤2,000 token（reviewer / critic ≤3,000）
## Boundaries - 禁止再派 agent - Do NOT: commit / push / 改 spec / 全量测试 - 失败时返回 tried / observed / hypothesis，同一失败最多 2 次
多视角时分开派发、不共享结论；第二视角只做「假设对照代码」
回顾

Value Review：离 North Star 还有多远，还在主线上吗

回答的只有这一件事。产物写给船长而不是日志：无内部代号，证据用路径指，判决先写完，人的答案是输入不是替代。永不自动落地。

  6. 贬值检查 由方向反方写

存储

什么写在哪：热存储有上限，冷存储随便长

backlog 膨胀的根因是内容没有指定的家；记录膨胀的根因是写入有规则、读回靠记忆。每 session 或每路由都要读的是热存储，有上限、条目到期；归档与 git 是冷存储，搬不删。

热存储每 session / 每路由都读 · 有上限 · 到期收缩

  • CLAUDE.mdNorth Star · Stack（项目参数）· Hard Rules 7 条，约 40 行常驻
  • backlog.md索引不是正文，≤8KB，hook 兜底；Now 整段覆盖
  • changes/<id>/change.md在途契约，与其改过的主 spec 段
  • docs/watchlist.md留给未来的条件；优先写到会被读到的地方（文件头 / Verify 断言 / Requirement 下一行）
  • docs/decisions.md只收人的四类裁定：日期｜裁定｜理由｜失效前提；技术决定不进这里

到期：两次里程碑汇总未触发或 ≥8 周 → AI 审后删行并在汇总列出；绑定具名未来事件的免到期。

冷存储随便长 · 搬不删 · git 有

  • changes/archive/归档的 change.md：过程、读数、gate 结果、失败注记、Decided:、事后订正
  • docs/specs/<cap>/spec.md能力契约 + Architectural Decisions（Source / Superseded / Fails when）；冻结能力移出日常读取
  • docs/retros/里程碑汇总 / project review
  • docs/notes/<date>-<slug>.md探针读数、方法教训、外部事实核实、反方全文；一题一文件
  • git log历史在 git；主线步完成只打勾，支线完成即删行

强制层

Hooks：只堵错路，不堵正路

文本约束是软约束，PreToolUse / PostToolUse hook 是硬约束：零上下文成本，去留只看误报率。硬 block 仅限「该项目里永远不合法」的行为，有合法例外的用软提醒。

PreToolUse · Bash|PowerShell · TIER 1 硬拦

block-unsafe-test-commands

阻断裸跑测试命令（无 filter、无 escape var）。重型测试默认并发把机器冻结，子代理的文本约束被实证不可靠，所以必须叠加 hook。模板三个占位符：TEST_CMD_REGEX / SAFE_FILTER_REGEX / ESCAPE_VAR。

Day-1 四问：有重测试吗 → 裸命令是否已由配置默认安全（是则极性反了，不装模板）→ 测试代码能改吗 → 会派 subagent 跑测试吗。

PreToolUse · Bash|PowerShell · TIER 2 软提醒

warn-destructive-git

reset --hard / push -f / checkout . / restore . / clean -f / branch -D 出现时给一行 JSON additionalContext。内环的「回锚点」是合法用法，所以只提醒不拦。

PostToolUse · Write|Edit|Bash|PowerShell · TIER 2

warn-backlog-size

backlog.md 超 8KB → exit 2 提醒搬内容。读的是载荷里的 cwd，不是进程工作目录。热存储上限的唯一机械兜底。

可见性法则工具事件下模型看得见的只有 JSON additionalContext 或 exit 2 + stderr；exit 0 + stdout 只进 debug 日志
编码法则脚本只含 ASCII；stdin / stdout / stderr 都显式 UTF-8；坏 JSON exit 1
路径法则matcher 必须 Bash|PowerShell；路径走 $CLAUDE_PROJECT_DIR，hook 的 cwd 跟工具当前目录走
部署法则没 echo 测过的 hook 不算部署：独立隐藏控制台跑、读进程退出码、挂载后真跑一次被拦命令

四条设计原则

下限锚定 Opus 5保留的约束必须对 Opus 5 有效；切除的必须 Opus 5 也不需要
不做单一模型特调模型校准是厂商的事；回归记录标注当时模型
内核 harness 中立契约格式、spec、CLAUDE.md 是纯 markdown；skills / hooks 是 Claude Code 适配层
提示层做减法「过度约束反噬能力」指提示层文本；hook 零上下文成本，只看误报率
数据逻辑进 CLI 命令skill 只编排，不嵌数据逻辑
不用正则审查自由文本能用真隔离或结构化手段时
不自定没人要求的契约「永不打 traceback」追不到任何判据
环境知识进 Stack 或知识库不散落
