## 2. 设计

### 2.1 backlog.md = 索引，不是正文

新模板 `templates/backlog.md`，四段固定：

1. **Now**（新 session 从这里接）：主线位置（含在途 change 与 task）/ 下一步 / 悬而未决 /
   支线计数。**整段覆盖，不追加**——覆盖前先读旧 Now，悬而未决只能核销或结转；历史在 git log。
2. **主线**：从当前进度到 North Star 成功判据的**有序路径**，按板块分组（无分组 = 整条主线
   一个板块；板块 = 一句终态）。每步一行：`- [ ] <change-id 或外部事件> — <一行 user-visible
   outcome>｜解锁判据 <n>`；冻结的步 `[~]` 带 kill 线与复活条件。完成只打勾。
3. **支线**：触发在望的维护 / 修复 / 待触发，一行一条带触发与来源；完成即删行。长尾 watch
   与冰箱（kill + 复活条件）进 `docs/watchlist.md`，backlog 留一行指过去。
4. **Done**：按板块折叠，一板块一行；change 细节在 archive。

预算：**全文 ≤8KB**（≈2.5k token；中文密度下约 45–80 行——字节是 token 的代理，行数方差
3 倍，故 hook 只量字节）。超了搬内容不删信息。规则写在模板头（每次 session 必读）与
change-loop Close；CLAUDE.md 不重复。

内容归属表（GUIDE §6，根因修复）：终态 / 判据 → CLAUDE.md North Star；运行须知 → CLAUDE.md
Stack；路径 / 下一步 / 触发在望的支线 → backlog；长尾 watch / 冰箱 → `docs/watchlist.md`；
change 过程 / 读数 / gate 结果 / `## Errata` → change 归档（OpenSpec：proposal.md 末尾）；
已定规格未开工的步 → 前置探针归档或 `docs/notes/`；架构决策 → ARCHITECTURE / DESIGN
Decisions；**change 之间的人裁定 → `docs/decisions.md`**（一行一条：日期｜裁定｜理由｜失效
前提）；探针读数 / 方法教训 / 外部事实 → `docs/notes/<date>-<slug>.md`；回顾判决 → `retros/`；
工具包流程问题 → toolkit FIELD-LOG。

harness 兜底：`warn-backlog-size` Tier 2 hook（PostToolUse，matcher `Write|Edit|Bash|PowerShell`；
Bash / PowerShell 命令提到 backlog.md 时检查 cwd 下的 backlog.md）——写后超 8KB 即以
exit 2 + stderr 回报模型。阈值确定性：只在字节数真超时报。源码内联在 project-bootstrap
Step 3（附录 G 冻结不动）。

### 2.2 subagent 常设授权 + gate 二元字段

- 模板 CLAUDE.md Hard Rule：gate 评审、spec 自检、高噪音隔离的派发是**常设授权**——不请示、
  不等批准；harness 对多 agent 编排的 opt-in 规则不适用于单个 subagent。派不出去 → 报原因
  并标 ungated，**不在本会话 inline 替代**。change-loop §4 补 harness 具体名（Workflow）与
  「R1+ 的 gate 定义是 fresh-context，inline 自检不是 gate」。
- change-loop §5 Close 必填行：`Gate: critic 跑了（n）| 没跑（原因）；reviewer 跑了（n / 视角）
  | 没跑（原因）`，R1+ 任一没跑 → 出口态 **DONE-ungated**（Loop Contract Exit 槽位同步）；
  R0 免 gate、不写 backlog、不计数。
- 迁移：grep 项目 CLAUDE.md 删除反向规则（subagent「用户确认后再开」等）。

### 2.3 Spec 自检（propose 后、apply 前）

change-loop §2 末尾：spec 成文后派 fresh-context **spec critic**（dispatch-prompt.md 变体）。
分级：R1 一个（只做清单第 2、5 条）/ R2 critic + 「假设对照代码」视角分开派 / R3 再加
skeptic（只看 proposal 的 Why 与引用的读数，不看 tasks）。顺序：critic → 修 [blocking] →
R2+ 把 critic 冲突项与「最不放心的 3 处」并列交人批准（R2 既有的人批准触点，不另加仪式）→
进循环。critic 派不出去 → 契约头记 `Critic: 未跑（原因）`，Close 的 Gate 行同列。

critic 清单（dispatch-prompt.md，7 条）：意图三向覆盖 / 对既有代码的每个假设去读代码核实 /
外部 API 与库实查 / 范围（tasks 超 spec？Non-goals 覆盖蠕变？Outcome user-visible？）/
可验证（每 Requirement 成功 + 失败 scenario；Verify 覆盖；末 task 端到端）/ 决策带为什么 +
失效前提 / 必填「最不放心的 3 处」。立场：默认找问题，报 PASS 前先说试过怎么打它。
**自检发现 ≠ 新 change**：范围内改 spec，超范围进 backlog 支线一行。

### 2.4 value-review 重构 → 两种回顾（skill 名不变，触发词保留）

**检查点**：下一个 change 路由前（change-loop §1 第一步），不在 Close 当场打断批次。

**Route check（航线校准）** `retros/<date>-route-check.md`，≤40 行。触发（任一）：
主线里程碑 archive 后（该步所标判据可观察达成）｜支线计数 ≥3（计数在主线推进或 route check
后清零；Now 下一步为「等 <外部事件>」期间暂停此条）｜最近 retro commit ≥4 周（backstop：任何
形式的 retro 都重置；命中而未写文件 = 未回顾，锚点不动）｜人问。

内容六项：终态与判据（抄 North Star）→ 主线快照（M 步已完成 k；本期 archive → 推进 / 前置 /
支线及为何出现；推进按用户产物核验，已证明 ≠ 已交付）→ 待做审视（只审在途提案 + 新增支线 +
触发已命中的，其余一句）→ 偏离判决（先写一行量：自上次主线推进起 n 支线 / d 天；判据：同一
细节 ≥2 个 change 且不是主线步、主线步估算较上份推后、目标措辞滑移、支线连击——主线阻塞于
外部事件时不算）→ 距离 → 下一步（唯一）。末两行：承诺核销；`模型: <会话模型名>`。

**Project review（工程复盘）** `retros/<date>-project-review.md`，≤120 行。触发（任一）：
板块收官（包含并取代同次 route check）｜最近 project-review ≥8 周（无则从最早 retro 或立项
commit 起算）｜模型换代（家族名或主版本号变化，对照上份 retro 末行）｜连续 2 次 route check
判「钻牛角尖」或位置未前进且两次间隔 ≥1 个主线尝试或 ≥2 周｜人要求。

内容七项（2026-09-11 用户裁定补两项）：North Star 还成立吗 → 地图倒核（剩余主线步全做完，判据真能
达成吗）→ 成功判据逐条（证据取自生产路径与用户产物）→ 轨迹（每板块计划步数 vs 实际 change 数 vs
用时）→ 死胡同 → 贬值检查（当前模型 / 工具已能直接做到哪些部分；剩余价值）→ 先写「停掉的最强
理由」再给建议 [continue] / [re-scope] / [pause] / [kill] + 主线重排提案。route check 第一行固定
问人「这段时间你用下来最不满意的一件事是什么」。skill 末尾带四个自检观察位（#4–#7），命中即在
retro 末尾写明并告诉人；信号与升级方式见 FIELD-LOG 2026-09-11。

共同规则：最多提 1 个新 change 且必须在主线上；回顾只读（需要新实验 = 它提的那一个 change）；
[decide] ≤3 条、每条是非题或 A/B、写完停下等人当场拍，未拍的结转 backlog Now；主线段增删
经批准；判决书不是日志；流程问题进 toolkit FIELD-LOG；首轮无主线段 → 先跑 bootstrap 迁移，
旧 `*-value-review.md` 视作上一份 retro。

节奏锚全部由命令得出（zd-tool 2026-09-02 R4 教训，按 commit 序不按文件名）：value-review
内联三条 git 命令；Now 里的支线计数只是缓存。

### 2.5 change-loop 路由与 Close

- §1 路由声明加第三行 `主线: 第 N 步 <id> | 第 N 步前置 | 支线（来源）`——不在 backlog 主线段
  的 change 一律支线；主线段只在 route check / project review 批准后或人指示时增删，Close
  只打勾。路由前先查回顾触发。
- §5 Close：Verify 输出 → Outcome → `Gate:` 行 → `主线:` 行 → 出口态 → 按 WORKFLOW
  §5.8.1–5.8.4 archive（§5.8.5 的 backlog 更新由本节取代）→ 更新 backlog（主线步 DONE 才打勾；
  支线完成即删行；Now 覆盖前先读旧 Now，债务结转；支线计数规则）。

### 2.6 project-bootstrap

- Step 1 brainstorm 新增产出：**主线路径**（格式见模板；外部事件也是步骤，带到期日或 kill 线）。
- Step 2：backlog.md 从 `templates/backlog.md` 起草（所有规模）。
- Step 3：hooks 5 → 6，加 `warn-backlog-size`；两条写法法则（可见性 / 编码）；
  `warn-route-before-opsx` 与 `warn-destructive-git` 改 JSON additionalContext；echo 用例三条
  + Bash 分支 + 坏 JSON，从 PowerShell 在 `chcp 936` 下用含中文的 UTF-8 载荷跑。
- 存量项目迁移（幂等，AI 起草 → 人确认后落盘）：backlog 瘦身五步（先按归属表抽条搬走，
  再删交接叙事，再压 Now，再压 watch / done，最后写主线段）；CLAUDE.md 对照模板补齐并删除
  冲突旧规则；重跑 Tier 2 hooks。

### 2.7 证据摘要（10 个 fresh-context reader 对 4 份 backlog + 14 份 retro + 1 份输入的结构化审读）

backlog：三个项目从未删除过任何内容，只加标记（【已归档】/ 划线 / `<details>`）；交接段
叠 12–16 层，两三个标题同时自称「新 session 从这里读」；读数在已有文件的情况下仍整表粘贴；
人裁定同一条复述 3–5 处；WORKFLOW §5.8.5「更新 backlog 标记 done」被执行成「把 Close 记录
追加到同一行」（finance_tool 单行 2.9KB）。无家可归的内容类型 ≥12 种 → §2.1 归属表逐一给家。

retro：逐 change 三分类在 40+ 个 change 上零次判出 self-indulgence；North Star 检查从未失败；
全部没有「终点 → 有序路径 → 距离」段；单份 6KB → 40KB 递增，「明天会发现」「反向自检」仪式段
使篇幅翻倍；触发最短间隔 1 天（小修 + 探针一天 9 份归档撞线）；一个窗口内 5/5 archive 全是
上轮 retro 的提案；单点兔子洞（zd-tool p14：33 点之一、地址早已正确，吃掉 6 个 change/probe；
review-engine 源文重合：5 个 change 横跨 3 份 retro）无人标注为漂移；终点定义在三份间漂移；
「必须由人拍」的 [decide] 当轮不拍、下轮重述；回顾自己跑实验；议题逐轮从产品滑向流程规则；
贬值检查 15 份中 1 份。

值得保留（已吸收进 §2.4）：承诺核销表、四判据状态表、「目标 → 差什么 → 病因 → 条目」表、
盲考 / 回归成绩分开、「已证明 ≠ 已交付」的生产路径核查、先量后判。

### 2.8 顺带修复的两处 harness 静默失效（契约在 FIELD-LOG 同日条目）

- 附录 G Tier 2「exit 0 + stdout」写法在工具事件下模型看不见（实跑证实）→ bootstrap Step 3
  写法法则；`warn-route-before-opsx` 内联改 JSON additionalContext；`warn-destructive-git`
  部署时同法改；SessionStart 类 hook 不受影响。
- PowerShell 5.1 按控制台代码页解 stdin，Claude Code 送 UTF-8 → 含中文的真实载荷解析失败、
  hook 静默 exit 0 → 脚本读 stdin 前显式设 UTF-8，坏 JSON 显式 exit 1；脚本只含 ASCII。

## 3. 不做

- 不改 skill 目录名（value-review 触发词与各项目引用保持）。
- 不加自定义 agent 定义文件（`.claude/agents/`）；若「拒派」复发，回装方式 = 定义只读 reviewer
  agent（FIELD-LOG ablation 台账登记）。
- 不动 WORKFLOW.md v3.6；不动知识库 2026-09-08 记录的 4 处待删项（用户另定）。
- 不主动迁移存量项目（触碰 = 下次在该项目起 session 时按 Session Start 的缺段判定触发迁移）；

## 4. 验证

- 尺寸（token 量是真指标，字节为速查；实测落点 change-loop 8.5KB / value-review 5.6KB /
  bootstrap 9.7KB / backlog 1.7KB / CLAUDE 2.0KB）：change-loop ≤9KB（≈2.3k token，仍为 v4 的一半）；
  value-review ≤6KB；project-bootstrap ≤10KB（含两段内联 hook 源码）；templates/backlog.md
  ≤2KB；templates/CLAUDE.md ≤2.5KB。
- 陈旧锚点 grep：`每 5 个 archive|≥5 archive|自嗨连击|Explored:` 在 skills/ 与 templates/ 零命中；
  `三分类` 仅剩 templates/CLAUDE.md 的 Outcome 定义（前瞻过滤，非回顾程序）。
- hook echo（PowerShell、`chcp 936`、UTF-8 中文载荷）：超 8KB backlog.md（中文路径 + 中文内容）
  → exit 2；小文件 / 其他文件 / 目录同名 → 0；Bash 命令提到 backlog.md 且 cwd 下超标 → 2；
  8192 B → 0、8193 B → 2；坏 JSON → 1；`opsx:propose` → JSON 一行、`opsx:proposed` / `change-loop`
  → 静默。
- 对抗自检：8 视角 fresh-context reviewer 审全部改动，[blocking] 修完再 commit（结果记 FIELD-LOG）。
- GREEN 观察位（下个项目回填）：backlog 是否稳定 ≤8KB；route check 是否只在主线边界与支线
  计数处发生；spec critic 首轮 blocking 数；「拒派」是否再现；软警告改 JSON / exit 2 后模型是否
  真的对提醒有反应，以及是否把 PostToolUse exit 2 误当 Write 失败。
