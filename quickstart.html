MY-WORK-SKILL · V4 · AI 工程开发工作流

人守 gate，AI 跑循环。

一套部署在 Claude Code 上的个人工程工作流：AI 按风险给每个变更选路由、自主执行开发循环、用真实命令输出向你交付证据。你只在关键决策点出手。

3 个 Skill 3 份模板 1 套 hooks 每条规则有实证出处

What

这是什么

给谁用：用 Claude Code 做真实工程（半天到数月）的个人开发者。

它不是又一个 prompt 合集，而是一套控制结构：约束放进 harness（hooks）和模板必填槽位里强制执行，流程知识做成 skill 在正确的时刻自动注入，人只审证据、不盯过程。

前身是作者在多个真实项目上迭代出的 v3 工作流（1800 行文档）。v4 把它压缩成 3 个 skill + 模板，并融合了 2026 年开源生态的循环工程实践——每条采纳与拒绝都有出处，台账见仓库 GUIDE.md §7。

How it runs

一次变更的完整旅程

01 · ROUTE

路由

AI 声明 R0–R3 风险等级和一行理由。小改零仪式，大改先立约。拿不准就往高判。

02 · CONTRACT

立约

写定成果（用户视角）、验证命令（具名）、预算上限、三态出口。

03 · LOOP

循环

一次一个 task：红 → 绿 → 审 → commit。坏树回滚到绿锚点；卡住自动切根因诊断，不硬刚。

04 · GATE

验收

证据包：每条 Verify 命令的真实输出 + 成果核对。收尾必是三态之一：DONE / BLOCKED / SPLIT。

路由判据流程与评审
R0 直接做一次 commit 可逆，不碰 spec / 架构测试 + 提交，inline 自检
R1 轻量意图 2–3 句说清，单一能力SPEC-lite → 循环，收尾单 reviewer
R2 标准新能力 / 跨模块 / 新外部依赖完整 propose，人批 spec，双视角评审
R3 架构动架构决策 / 数据契约 / 北极星先 brainstorm，人拍方向，三视角评审

Capabilities

它替你防住什么

防跨步瞎干

约束下沉：hook 物理拦截 > 模板必填槽位 > skill 按需注入 > 常驻文本。文本靠不住的地方，用结构和代码兜底。

防空转硬刚

stuck 判据（空 diff / 同错误连续两次 / 修 A 坏 B 往返）命中即停，切根因诊断或如实报 BLOCKED——不换着说法重试。

防技术自嗨

每个变更必须写出用户视角的成果；只能用「重构 / 统一 / 抽象」描述的活，会被拦去 value-review 由你裁决。

防假完成

验证 = 具名命令 + 期望输出，「应该没问题」是违禁词。评审发现分诊 [blocking] / [nit]，防评审驱动的过度工程。

防丢上下文

状态永远在文件里（Loop Contract / tasks / 失败注记），落地即提交。短会话 + 文件交接，优于长会话硬扛。

模型分层，省钱不降质

产出可以便宜，裁判不能便宜：机械可验证的活派便宜模型（附行动规范整块），评审与诊断永不降级。

Why this

相比其他做法的差别

对比差别在哪
vs 裸用 Claude Code多的不是流程，是回退与终止的保证——绿锚点、三态出口、预算封顶。AI 永远处于可回滚、可交接、可验收的状态。
vs v3 工作流文档人工触点从每阶段确认减到每变更最多 2 个 gate；1800 行文档压成正确时刻自动注入的 skill；数值判据有单一权威源，不再漂移。
vs 重型框架为一个人设计。没有角色扮演开销（BMAD 类），没有 20 个 agent 的编排成本，仪式跟风险挂钩——小改动零仪式。

Quick start

五步上手

前置条件

Claude Code（保持最新）、git；中型项目另需 Node ≥ 20。安装 superpowers 插件：

/plugin marketplace add obra/superpowers-marketplace
/plugin install superpowers@superpowers-marketplace

冷启动（仅第一台机器一次）

clone 本工具包到本地，在项目目录让 AI 读 skills/project-bootstrap/SKILL.md 并照做。skill 装好后，这条手动路径永久退役——后续部署与更新都由 AI 完成。

说「立项」

之后 project-bootstrap 接管：先 brainstorm 立项（你回答问题），再由 AI 回填 NORTH_STAR.md / CLAUDE.md /（中型）ARCHITECTURE + backlog——你逐行确认，不用从零填模板。North Star 生效后只有你能改，AI 只读。

hooks 与 Opus 注入自动配好

立项收敛、stack 已知后，AI 按 WORKFLOW.md 附录 G 部署 hooks 并跑通验证用例（重型测试项目含测试命令拦截——唯一 100% 可靠的约束层），再把模型感知的 claude wrapper 写进 PowerShell $PROFILE：它自己解析本次会话的模型，是 Opus 就自动注入 OPUS-SYSTEM.md——直接敲 claude、从不碰 --model 的习惯也覆盖，不再靠手动。

开工

直接说需求。AI 先给出四行路由声明（Route / Explored / Mode / Next）再动 spec 或代码——从这一刻起流程就在运转了。第一个 change 也不例外：从 change-loop 开始，不从 propose 开始。

Your role

你只在三种时刻出手

批 spec（R2+）

看 proposal 是不是你想要的东西。这是全流程 ROI 最高的几分钟。

验收证据包

看命令输出，不听口头汇报。三态出口让「做没做完」没有灰色地带。

value-review 拍板

每 5 次归档或 4 周自动触发。方向性结论（架构、backlog、北极星）只有你能定。

Notes

四件事先知道

AI 停下来问你 ≠ 卡壳。新能力类 change 默认先走一轮短 brainstorm——这是设计不是含糊；语义级模糊（需求含义、边界、设计意图）按规则必须问；实现级细节它会自己定并留一句注记。
BLOCKED 不是失败，是诚实。它附带「试过什么 / 观察到什么 / 假设是什么」，比硬刚出一个假完成有价值得多。
这套 skill 处于实战验证期。发现 AI 绕规则时，把它的原话记下来——回填 skill 的 rationalization 表正是这套体系的进化方式。
无人值守模式先别碰。GUIDE.md §6 有完整 recipe，但防护清单全部满足、白天陪跑几次之后再考虑过夜。
